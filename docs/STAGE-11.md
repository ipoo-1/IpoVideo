## 3. 核心概念

### 3.1 简历项目的三条铁律

1. **只写你做过的**：没实现的不写，简化的标注“简化版”。
2. **用动词开头**：设计、实现、优化、接入。
3. **可被追问**：简历每一条，你都要能展开讲 2 分钟。

### 3.2 STAR 结构

```text
S 场景：长视频分析慢、成本高、结果不可信
T 任务：让用户提交目标后异步完成可追溯分析
A 行动：RocketMQ 异步 + VideoContext + AgentLoop
R 结果：提交即返回，结论绑定时间戳证据
```

## 4. 简历项目描述（模板）

> **IpoVideo：面向长视频内容理解的 AI Agent 平台**
>
> 技术栈：Java 21、Spring Boot 3、MyBatis-Plus、MySQL、Redis、RocketMQ、
> MinIO、Qdrant、LangChain4j、DeepSeek、FFmpeg、Tesseract
>
> - 实现注册登录与媒体管理，密码 PBKDF2 加盐哈希，会话存 Redis 并做登录限流；
> - 基于 RocketMQ 将分析任务异步化，消费者幂等执行，Redis 分布式锁防重复提交；
> - 使用 MinIO 对象存储实现大视频分片上传与断点续传，数据库仅存元数据；
> - 通过 FFmpeg 抽音频/关键帧 + ASR/OCR 构建带时间轴的 VideoContext，
>   接入 Planner-Executor-Critic Agent 生成结构化结论；
> - 使用 BGE-M3 + Qdrant 实现片段向量检索，不可用时降级关键词匹配；
> - 使用 Flyway 管理数据库迁移，编写集成测试与 Docker/CI 配置。

## 5. 面试讲解路线（5 分钟）

```text
1. 一句话：这是一个把长视频变成可追溯知识的 AI 平台
2. 主链路：上传 -> MQ -> 消费者 -> VideoContext -> Agent -> 结果
3. 三个难点：
   a. 长耗时任务怎么异步可靠（MQ + 幂等 + 状态机）
   b. 模型结论怎么可信（证据约束 + Critic + 轮次控制）
   c. 上下文太大怎么检索（Embedding + Qdrant + 降级）
4. 总结一句：中间件都是为产品问题服务的
```
