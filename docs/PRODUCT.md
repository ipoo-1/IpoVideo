# IpoVideo 产品分析

## 一句话定义

IpoVideo 把长视频（网课、会议、操作录屏）变成**可检索、可追溯、可追问**的结构化知识。

## 目标用户与典型场景

| 用户 | 场景 | 期望产出 |
| :--- | :--- | :--- |
| 学习者 | 2 小时数据结构网课 | 核心知识点、时间戳证据、复习题 |
| 职场人 | 冗长会议录音录像 | 结论、待办、关键发言位置 |
| 教程作者 | 软件操作录屏 | 步骤清单、截图、命令 |

## 核心痛点

1. 重看成本高：想在 2 小时视频里找一句话，只能拖进度条。
2. 总结不可信：AI 凭印象总结会编造内容，用户不敢直接使用。
3. 重试成本高：1 小时视频处理到一半失败，不能要求用户从头再来。

## 产品价值

把"时间型信息"变成"结构型知识"：

- **可检索**：不用重看视频，按目标快速召回相关片段。
- **可追溯**：每条结论都绑定原视频时间戳，可以点回去验证。
- **可追问**：围绕同一个视频继续提问，不重复处理原始视频。

## MVP 定义

第一版只做四件事：注册登录、上传视频、触发分析、查看结果。
这个版本允许分析慢、允许失败，但必须让用户完整走一遍主流程。

产品思维要点：**先验证用户愿不愿意用，再优化能不能扛住规模。**

## 成功指标

- 一次分析的平均耗时与失败率
- 结论可追溯到时间戳的比例（可追溯率）
- 追问是否复用已有结果（AI 成本节省）

## 产品如何决定架构

| 产品问题 | 工程解法 | 对应阶段 |
| :--- | :--- | :--- |
| 视频文件大、网络差 | 分片上传、断点续传、对象存储 | Stage 6 |
| 分析耗时几分钟到几小时 | 异步任务、消息队列、SSE 进度 | Stage 3/5 |
| AI 接口不稳定、会失败 | 重试、超时、熔断、降级 | Stage 4/7 |
| 多用户抢资源 | 限流、分布式锁 | Stage 4 |
| AI 结论不可信 | 证据约束、Critic 校验、可追溯 | Stage 7/8 |
| 长视频上下文太大 | 切片、摘要、向量检索 | Stage 8/9 |

后面每一个阶段，我们都会从这张表里拿一个真实问题出来解决，而不是为了"加中间件"而加中间件。
